# G-Call 自動付与

Android 10（API 29）以上の通常の電話アプリから発信するとき、国内番号に `0063` を付与する小規模アプリです。Kotlin / Jetpack Compose / CallRedirectionService / DataStore Preferencesを使用します。

## 構成

```text
app/src/main/
  AndroidManifest.xml
  java/jp/example/gcallprefix/
    MainActivity.kt                1画面の設定・RoleManagerによる有効化
    GCallRedirectionService.kt      Telecomへの応答・緊急通報確認
    PrefixRule.kt                   Androidに依存しない番号判定
    SettingsRepository.kt          DataStoreによるON/OFF保存
    CallHistory.kt                 処理結果・履歴モデル・20件制限
    HistoryRepository.kt           別のDataStoreに履歴保存
  res/                             ラベル・テーマ・アイコン
app/src/test/java/jp/example/gcallprefix/
  PrefixRuleTest.kt
  CallHistoryTest.kt
```

## 動作と安全設計

- 初回起動はOFF。DataStoreに保存できたON/OFFを表示します。
- ONかつAndroidの「通話リダイレクト」ロールがこのアプリに設定されている場合に動作します。
- `09012345678` → `006309012345678`、`0312345678` → `00630312345678`。
- `110` / `118` / `119`、`0120` / `020` / `060` / `0570` / `0800` / `0990` / `0063`で始まる番号、`#` / `*`で始まる番号は変更しません。
- ハイフン・ASCII空白・括弧を除去して判定。除外時は元のURIをそのまま使用します。
- AndroidがE.164形式で渡す場合に備え、`+819012345678`は`09012345678`へ変換してから付与します。`+81`形式の除外番号にも付与しません。
- 対象は国内固定電話の形式に一致する10桁と、050・070・080・090の11桁です。固定電話は011〜019、022〜029、03、042〜049、052〜059、06、072〜079、082〜089、092〜099の地域番号の形式を判定します。03・06の直後は1〜9に限定し、0170・0180・0190等の特殊サービス番号と上記除外番号は変更しません。割当済み・実在・開通済み番号の保証はしません。
- `00…`の事業者プレフィックス、`010…`の国際発信、その他の国際番号、短縮番号、非数字やポーズ（`,` / `;`）を含む番号、MMI/USSD、`tel:`以外のURIは変更しません。
- `184`（非通知）／`186`（通知）は一つだけ分離して相手先を判定し、`184006309012345678`／`186006309012345678`の順に維持します。`184+819012345678`も同様に変換します。184／186付きの除外・緊急番号や既付与番号は元のURIを維持。184／186の重複・混在は変換しません。通知動作は端末・回線でも確認してください。
- G-Call公式FAQの非対応一覧に合わせ020・060・0990を除外しています（2026-10-05確認）。060は今後の対応変更があり得るため、G-Callの対応確認後に見直してください。
- Android Telecomは緊急通報をCallRedirectionServiceに渡しません。さらに元番号・184／186を除いた相手先・国内形式・0063付与後・184／186を含む変更後番号を`TelephonyManager.isEmergencyNumber()`で確認し、どれかが緊急番号なら`redirectCall()`を呼びません。判定不能・例外時も変更しません。
- 設定読込と番号判定はIOスレッドで行い、1.5秒で待機を打ち切ります。別途メインスレッドの2.5秒フォールバックで未応答の場合に元番号で応答します。応答は一度だけです。Telecom自体には5秒の期限があり、OSやプロセス停止でアプリが応答できない場合はOSが発信を中止する場合があります。
- 発信に使用するSIM（PhoneAccountHandle）を維持します。デュアルSIMの選択は標準電話アプリで行ってください。
- 発信処理履歴に電話番号をマスクせず保存します。端末内のみで直近20件まで保存し、画面の「履歴を削除」で全件削除できます。番号をログ出力・外部送信しません。バックアップ・端末間移行も無効です。

INTERNET、連絡先、通話履歴、電話発信、電話状態などの権限を要求しません。Manifestの`BIND_CALL_REDIRECTION_SERVICE`はサービスにAndroidが接続するための保護であり、アプリが要求する`uses-permission`ではありません。Accessibility Service、root、Analytics、広告、外部サービスSDKは使用しません。依存はGoogle/AndroidXの公式ライブラリとKotlin coroutines（テスト用JUnitを含む）です。AndroidXが結合Manifestに追加するアプリ固有の署名保護権限`DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`は含まれますが、ユーザーへの権限要求はありません。ビルド時の依存取得にはPCのネット接続が必要ですが、アプリにはネット権限がありません。

## ビルド

Android Studioでこのフォルダを開いてGradle同期してください。SDK 36、Build Tools 36.0.0、JDK 17以上（Android Studio同梱JDK推奨）が必要です。AGP 9.0.1の組み込みKotlin 2.2.10、Compose Compiler 2.2.10、Gradle 9.1.0を使用します。

```sh
# Android Studio同梱JDKを使うmacOSの例
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
# 他の環境ではAndroid StudioのSDK Locationをlocal.propertiesにsdk.dirとして設定
./gradlew testDebugUnitTest assembleDebug lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

リリース配布時はAndroid StudioのGenerate Signed App Bundle / APKで自分の署名鍵を設定してください。debug APKは検証用です。

## 実機の設定

1. Android 10以上、音声通話できるSIMのある端末にインストールします。
2. アプリを開き「Androidの設定を開く」を押します。
3. Androidの通話リダイレクトアプリ選択画面で「G-Call 自動付与」を選び、許可します。標準の電話アプリを置き換える必要はありません。
4. アプリに戻り「Call Redirection Service: 有効」を確認し、スイッチをONにします。
5. 標準電話アプリから、同意を得た相手の実際の電話番号へ発信します。例示番号を実際に発信しないでください。

ロールとスイッチは別です。OFFにすると付与を止めます。ロールを解除するには端末設定の「アプリ」→「既定のアプリ」→「通話リダイレクト」（名称は端末により異なる）で解除・変更します。設定から戻ると状態を再確認します。

### Xiaomi / Redmi / POCO / HyperOS

最初に上記のAndroidのロール選択を使ってください。設定の「アプリ」→「アプリを管理」→メニューの「その他の設定」→「既定のアプリ」などに項目がある場合もあります。機種・地域・OS版でメニュー位置は異なります。設定検索の「通話リダイレクト」「既定のアプリ」も確認してください。

サービスが有効なのに付与されない場合は、次の順に確認します（メーカー固有の制限に対する確認手順であり、全機種で必要という意味ではありません）。

1. アプリを一度起動してONと「有効」を確認。強制停止した場合は開き直します。
2. 設定→アプリ→権限→「バックグラウンド自動起動」で本アプリを許可。設定検索の「自動起動」でも探せます。Xiaomi公式の14T向け説明ではこの経路が案内されています。
3. アプリ情報の「バッテリーセーバー」等で、制限がある場合は「制限なし」を選択し、再テストします。表示名・選択肢は端末により異なります。
4. 再起動後、画面ロック後、アプリを最近使ったアプリから閉じた後の各状態で、同意済みの非緊急番号を用いて確認します。

実機で「G-Call 自動付与から通話を発信することができません」という表示が出て履歴も残らない場合は、サービスの起動・応答が省電力制限で妨げられている可能性があります。ユーザーの実機ではバッテリーセーバー無効化後に動作しました。まず本アプリに対する「制限なし」設定を確認してください。全端末での改善を保証するものではありません。

HyperOSの一部端末でロールが提供されない場合、画面に「この端末では利用できません」と表示します。公式APIだけでロール非対応を回避することはできません。機種上での動作確認は必要です。Accessibilityやrootによる代替処理は実装していません。

### 実機での通常発信と状態保存

- G-Call契約・利用回線が0063方式を利用できることを確認してください。アプリは契約や適用料金を確認しません。
- 同意済みの相手の番号でOFF→通常発信、ONかつ有効→0063付与を確認。G-Callの利用明細と端末の発信表示などで確認します（電話アプリは元番号を表示する場合があるので表示のみでは確定しません）。
- 0120 / 0800 / 0570は実在し、試験発信が許される番号だけで確認。0570などは課金に注意してください。
- ON状態でアプリ再起動・端末再起動後もスイッチの保存を確認。
- Android設定でロールを解除→戻ると「無効」。付与されないことを確認。
- デュアルSIMは各SIMで確認。ロック中やバックグラウンドでも確認。
- 可能ならAndroid 10と最新Android、Xiaomi/HyperOS実機を含めて確認。エミュレータの単体テストだけではSIM・キャリア経由の動作を確認できません。

## 発信処理履歴

画面下部に新しい順で直近20件を表示。発信時刻、Androidからサービスに渡された番号（マスクなし）、リダイレクト応答済みの場合の変更後番号、処理結果を保存します。電話アプリに入力した書式や国番号がAndroid側で変換されている場合があります。184／186は、サービスに渡された場合に記録されます。

結果は0063付与、OFF、除外番号、対象外形式、緊急番号、緊急判定不能、設定読込失敗、処理タイムアウト、Android応答期限超過、Androidへの応答失敗を区別します。「0063付与」はリダイレクト応答済みを意味し、接続・通話成立・G-Call料金適用の確認ではありません。

履歴は設定とは別のDataStore PreferencesにJSONで保存。Androidへの応答を先に行い、その後にプロセス内のIOコルーチンで記録します。保存失敗は発信結果に影響させません。OSによるプロセス終了等で未記録になる場合があるため、完全な監査ログではありません。ロール無効時やAndroidがサービスに渡さない緊急発信・ゲートウェイ付き発信は記録されません。通常の画面ロック中も、最初のロック解除後であれば保存対象です。再起動直後の初回ロック解除前には対応していません。

「履歴を削除」は既存の履歴だけを削除し、ON/OFF設定を維持します。削除と同時進行の発信や後続の発信は、新たに記録される場合があります。

実機確認では、同意済みの通常番号でON/OFFの結果と変更後番号を確認し、アプリ再起動後の保存、21件以上での20件制限、削除後の空表示とON/OFF維持を確認してください。緊急番号の実発信テストは行わないでください。単体テストは結果分類、緊急保護、番号の非マスク保存モデル、20件上限、時計変更時の順序を検証します。DataStoreの実保存・サービス応答・画面動作は実機確認が必要です。
